Working set is resident process memory, including shared pages. Private commit
is a different accounting value, not a claim that the process occupies that
amount of physical RAM. These values must not be added together. The large
commit increase with elevation was reproduced in the ADLX-only diagnostic;
it should not be attributed solely to PawnIO.

Combined diagnostic: initialization 440 ms; first sample 4.76 ms, subsequent
samples about 0.21-0.47 ms. Over 12.016 seconds, GetProcessTimes increased by
0.0156 CPU seconds, about 0.0081% of the entire 16-thread CPU. This is a short
measurement with finite timer resolution, not a zero-overhead guarantee.
It excludes the editor, renderer, USB transfer, and any separately accounted
driver/service work. Whole-application measurements must be taken separately.

Whole-agent observation from a separate 40-second run on this machine:
  LCD connected, periodic output active, no editor processes running.
  CPU utilization normalized over all 16 logical processors: 0.03416%.
  Working set: 36.918 MiB; private commit: 72.984 MiB.
This includes native rendering and USB output. It remains a short observation
under the current scene and update interval, not an upper bound for all scenes.

Renderer and IPC validation
  A native test decoded the produced PNGs and verified transparent overlay
  corners, visible text, empty transparent overlays, opaque background color,
  and 720x720 dimensions. Across 96 renders after warm-up, process handles
  stayed at 134, GDI handles at 3, and private commit at 6,127,616 bytes.
  Working set increased by 45,056 bytes. This short run finds obvious leaks;
  it is not a long-duration endurance test.
  The integration_test.py script verifies normal-user IPC, preview PNG checksums
  and pixel color, no scene mutation by preview, and rejection of an invalid
  scene without mutation. It sends no device-control commands. A 12-preview
  run observed stable resident memory; the engine was already outputting to
  the LCD, so those values include more than the isolated sensor diagnostic.

These are observations on this machine and driver versions, not resource
requirements or promises for other systems. Source tests use synthetic numbers
only for renderer assertions; runtime sensor providers never fabricate values.
